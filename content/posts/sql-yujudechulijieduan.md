一个 SQL 语句——简称查询——主要分为四个阶段进行处理：

1. **解析阶段**：这是第一个阶段，专门的组件——解析器，负责处理语句的文本形式（SQL 代码），并验证其是否正确。如果语句有任何语法错误，执行会在这一阶段停止；否则，解析器会将语句拆解成主要部分，例如，涉及的表和列的列表、数据过滤的条件、排序等。

2. **重写阶段**：当解析器成功完成后，语句进入第二个阶段——重写阶段。重写器负责应用语法规则，将原始 SQL 语句重写成实际执行的形式。特别地，重写器负责应用规则（参考第 8 章，触发器与规则）。当重写器完成任务，生成数据库将处理的有效语句时，语句会传递到下一阶段：优化。

3. **优化阶段**：在优化阶段，查询会由优化器处理，优化器负责找到访问数据的最快路径。找到这条最快路径并不是一件简单的事：优化器必须决定在所有可用的访问方法中，如索引或直接访问，选择哪一种方式来访问数据。正如你可以想象的那样，在所有可用访问方法之间进行推理和迭代需要消耗时间和资源，因此优化器的任务不仅是找到最快的访问方法，而且还要在短时间内找到它。

4. **执行阶段**：最后，当优化器决定如何访问数据时，查询会进入最后一个阶段：执行阶段。执行阶段由执行器组件处理，执行器负责实际访问存储并使用优化器决定的访问方法检索（或插入）数据。

# PostgreSQL SQL 执行阶段解析

在 PostgreSQL 中，SQL 语句的执行大致可以分为以下几个阶段：

## 1. **解析（Parser）**
   这个阶段的主要任务是将 SQL 语句转换为解析树（Parse Tree），以便后续处理。
   - **词法分析（Lexical Analysis）**：将 SQL 语句拆分为标记（tokens）。
   - **语法分析（Syntax Analysis）**：检查 SQL 语法是否正确，并生成解析树（Parse Tree）。

## 2. **重写（Rewriter）**
   该阶段主要用于应用 **规则（Rules）**，对解析树进行修改，以实现视图替换等功能。
   - 例如：当查询一个视图时，Rewriter 会将视图的查询转换为基础表的查询。

## 3. **优化（Planner/Optimizer）**
   在这一阶段，PostgreSQL 会基于 **统计信息和成本估算** 选择最优的执行计划：
   - **查询改写**（例如：常量折叠、子查询去关联化）
   - **访问路径生成**（例如：索引扫描、顺序扫描、哈希连接、嵌套循环等）
   - **成本估算**（根据 `pg_statistic` 统计信息评估不同执行计划的开销）
   - **执行计划选择**（选择代价最小的执行计划）

## 4. **执行（Executor）**
   这一阶段会按照 **执行计划（Plan Tree）** 实际执行查询：
   - **扫描（Scan）**：从存储引擎读取数据（如 `Seq Scan`、`Index Scan`）。
   - **联接（Join）**：执行表连接（如 `Nested Loop`、`Hash Join`、`Merge Join`）。
   - **聚合（Aggregate）**：计算 `GROUP BY`、`COUNT()`、`SUM()` 等聚合函数。
   - **排序（Sort）**：处理 `ORDER BY` 和 `DISTINCT`。

## 5. **返回结果**
   - 查询执行完成后，PostgreSQL 会将结果返回给客户端。

### **执行流程示意图**
```
SQL 语句
   ↓
词法分析、语法分析（Parser）
   ↓
查询重写（Rewriter）
   ↓
查询优化（Planner/Optimizer）
   ↓
查询执行（Executor）
   ↓
返回结果
```

这个过程涵盖了 PostgreSQL 执行 SQL 语句的完整流程，不同 SQL 语句（如 `SELECT`、`INSERT`、`UPDATE`、`DELETE`）在执行时可能会有部分差异，比如 `INSERT` 可能涉及 **WAL 日志** 和 **缓冲区管理**，`UPDATE` 可能触发 **TOAST** 机制等。
